# BreezeTravel 双模式产品定义

状态：项目所有者于 2026-09-05 批准。本文替代此前“旧房间永不进入产品”的单模式约束；旧 G07、旧 R0 和历史候选证据只作诊断，不能拼接为本版本通过。

## 产品结构

BreezeTravel 是一个账号、两种独立体验：

1. **行程查**是默认入口。用户匿名粘贴攻略文字，系统整理逐日卡片、核对地点和步行／公交路线，并给出最多三项可靠检查。
2. **协同规划**从顶栏进入且必须登录。它恢复创建／加入房间、多人同步、AI 问答、选择地点、高德地图和用户明确触发的驾车排线。

两种模式共享账号和天空蓝、青蓝、暖白的视觉语言，但不共享正在编辑的状态。唯一连接是“协同规划 → 转入行程查”：读取当前成员最近一次成功保存的路线，将允许字段规范成文字后重新进入 v3 理解与地点核验。行程查不会反向覆盖房间，旧房间、聊天和路线始终不变。

TripCheck 只提供已验证的界面与行为参考，不复制其仓库、解析器、数据库、Git 历史或依赖配置。第一轮只接受文字；历史 OCR 代码与 migration 只作冻结兼容资产，普通运行时、公共接口和本轮测试／Gate 均不激活、不要求、不验证 OCR、截图上传或图片理解。地点插画只作装饰。

## 行程查体验

首页不要求登录、选城市、日期、人数或房间，只提供文字输入、示例和真实回访入口。北京、上海、杭州提供深入地点与路线核对，其他国内城市提供保守的基础整理。失败保留输入和原请求身份。

结果页固定三个用户视图：

- **行程**：生成完成后默认进入。一天一行横链，所有日期共享一次横向平移，固定日期标题；卡片 180–220px，连接器为不表达真实距离比例的弧线。手机仍是横链并提供等价列表阅读。
- **地图与住宿**：真实高德地图为主体，底部显示当前日精简横链；目录、卡片、标记和路段双向联动。地图只消费服务端 `MapRenderView`，不在浏览器搜索 POI、计算路线或补画推测线。住宿建议保留。
- **优先检查**：最多 Top-3，标签只为“必须调整／可以更好／需要确认”，不显示内部代码、证据、版本或 Provider。

拖动只能从把手开始。松手只形成绑定当前结果的本地影响预览；取消零写入，确认才恰好发送一次现有 `ACTIVITY_MOVE`。写入成功后旧交通立即显示“路线需要更新”，只有用户明确点击才重新计算。

保留编辑、替换、移动、删除、新增、撤销、保存、住宿、分享、隐私删除、并发冲突和失败恢复。所有对话使用可访问组件，不用 `window.prompt/confirm`。触控目标至少 44px，键盘操作与焦点恢复必须等价。

## 渐进生成、停止与恢复

复用现有 SSE 和 `Last-Event-ID`，事件流优先，轮询仅降级。用户依次看到“已收到文字 → 日期与待确认卡片 → 地点核验进度 → 权威结果 → 异步地图与住宿”。临时快照严格只读；若要立即修改，先“停止整理”，将最后累计快照固化为可编辑的部分结果。

断线先读权威进度快照，再从该资源自己的游标续订。重复／倒退事件忽略，旧任务不能覆盖新任务。服务端只在结构完成和最多三个地点进度点保存累计快照，不推送逐字模型输出。

取消与完成通过 PostgreSQL 行锁竞争，先提交者生效。取消清除租约，迟到 worker 不能写回。有快照返回可编辑部分结果；无快照诚实返回已停止且无结果。

## 路线预演与 PNG

路线预演只读取当前有效 `MapRenderView` 的真实几何，支持播放、暂停、上一站和下一站，并标注“计划路线模拟”。它不自动播放、不发 Provider 请求、不宣称实时定位。无几何时退化为逐站卡片预演并说明动画不可用。

横链 PNG 由浏览器内确定性 SVG／Canvas 渲染结构化结果，不截当前视口、不调用图像服务、不保存到服务器。图片包含所有日期、卡片、交通摘要、待确认、路线过期和受限状态。渲染期间 ETag 改变则终止并提示重试。地图底图和照片不是首版成功条件，无图时明确“未包含地图”。

## 协同规划体验

`/collaborate` 提供创建房间、加入邀请和最近房间，进入后沿用 `/room/[roomId]` 核心布局并统一换肤。普通登录默认回行程查；由协同入口触发登录才返回协同规划。

内部继续使用实际四节点图 `router → tool_executor → synthesizer → critic` 和独立路线优化器，但普通界面只显示“理解需求／查找地点／整理建议”。节点名、思考链、Provider、版本、receipt、trace 和引用 ID 不进入响应、DOM 或本地存储。长期记忆默认关闭；RAG 缺失只减少建议，不能生成地点事实。

协同模式保留驾车规划，但只有用户点击“智能排线／重新规划”才可调用路线能力。浏览器挂载、恢复、地点变化和普通编辑均不得自动算路。直线距离只可作内部排序启发，不得展示为驾车时长、成功路段或精确到达时间；高德失败显示“路线暂不可用”且不画估算线。

精简运行时只挂载房间、成员、WebSocket 令牌、地点、AI 问答、排线、天气、行程保存与转换所需 API。Yjs 使用独立受鉴权进程、持久化和令牌刷新；旧入口仍不可访问。任何网络或持久化失败不得伪装创建、加入、保存、排线或同步成功。

## 转入行程查

只有最近一次成功保存路线后才显示“转入行程查”。服务端验证登录、房间成员和保存路线归属，只从数据库读取当前成员的最新路线。客户端只提交 `room_id`，不得提交地点事实、坐标或旧路线。

服务端只白名单提取城市、Day、时间、地点名称、类别和顺序，丢弃坐标、照片、描述、RAG、旧驾车耗时、直线估算和 Provider 成功声明。规范文本按加密 `TEXT` 保存并重新进入当前 v3 流程；旧房间和路线标识只以哈希进入内部幂等绑定。转换生成新的账号私有行程，无法重新确认的地点显示待确认。

## 永不降低的底线

- 错城、错类别、描述句或 URL 不能被自动确认为地点。
- 未确认地点必须明确“待确认”；未知／不可用不能显示成功。
- 不能泄漏越权数据、完整原文、秘密或内部字段；删除失败不能显示成功。
- 编辑、拖动、渲染和房间恢复不得自动调用路线 Provider。
- 缺失或不合理路线不绘制推测几何；红色只用于证据可靠的硬冲突。
- 失败后不得空白、无限加载或无法恢复；协同网络失败不得继续本地假流程。

召回率、边缘日期识别、非关键性能、动画和非核心浏览器可在两种修复策略后诚实降级；上述安全底线不能降低，只能关闭自动能力并回退到待确认／LIMITED／UNAVAILABLE。

## 数据与技术边界

采用同一 Next.js／React 前端和 FastAPI／Pydantic 模块化单体。PostgreSQL 是所有权、不可变版本、任务、幂等、租约和协同保存的事实源；Redis 只缓存、限流和可重建状态。v3 现有 URL、字段、ETag 和命令保持兼容，只增加批准的进度字段、取消接口、协同转换接口及一份追加式 `CANCELLED` migration。

不合并两个仓库，不恢复 OCR，不建设新的质量评分、RAG、记忆、路线算法或治理系统。不部署生产、不发布、不合并 `main`；R1 面向其他真实用户前仍需所有者批准。
