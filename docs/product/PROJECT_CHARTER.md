# 行程查产品定义

状态：项目所有者已批准重建；2026-09-05 生效。

## 用户需求与第一版流程

用户粘贴攻略，不填写前置表单，也不理解内部术语。系统整理逐日安排、确认真实地点与路线，发现可执行性问题，提供可预览的修改，并支持保存、刷新恢复和撤销。

完整路径：匿名粘贴文本 → 理解日程 → 核对地点 → 行程与真实地图 → 问题 → 修改预览 → 采纳 → 用户主动更新路线 → 复检 → 保存与撤销。

北京、上海、杭州提供深度地点与路线能力。其他国内城市只做基础整理并明确未核验部分。当前只接受文本，不恢复 OCR、截图、网页抓取或跨城交通规划。住宿及带来源建议保留为次级内容，首版不扩展。

## 用户界面

首页直接呈现文本输入、一个主按钮和示例入口。自定义输入使用真实服务，示例通过独立固定回放入口呈现。

桌面左侧纵向逐日行程、右侧真实高德地图，地点与地图双向选择联动。顶部提供日期切换、保存和撤销；地点详情允许候选更换、时间与停留编辑、移动和删除。问题放在对应日期或地点旁，展开后说明原因、修改前后和操作。

手机默认纵向行程，通过“行程／地图”切换。不使用横向地点卡片、多层嵌套滚动或大面积宣传。近白背景、深色文字、单一低饱和强调色，以排版、留白和分隔线建立层级。正文 14–16px，辅助字至少 12px；只有可靠来源的实景图才用于详情，缺图时保留文字。

普通用户只看到旅行内容、必要操作和“必须调整／可以更好／需要确认”。不得显示模型、Provider、内部阶段、置信度、原文映射、UID、hash、revision、receipt 或堆栈。红色只表示可靠证据支持的硬冲突；缺少信息和服务不可用使用非阻断提示。

## 理解与事实

模型负责理解日期、顺序、地点、取消、备选、时间和停留要求；服务端负责结构验证、搜索资格与地点事实核对。取消、备选、参考和途经描述不自动成为执行路线。不依赖持续增加中文词根补丁重写模型语义。

不确定安排保留为待确认项，明显内容未整理时不能宣布整份完成。缺省值为可编辑软假设，不伪装为原文明示事实。未知地点可搜索真实候选，由用户选取后服务端确认；客户端不能提交已验证坐标。不得自动匹配错城、错类别、描述句或 URL。

卡片先显示，地图在后台准备。局部失败保留已有结果并提供对应重试入口。地点坐标使用 GCJ-02，独立记录与活动的关联；单地点、重复名称、缺折线仍可使用。

## 时间、问题与修改

结构化保存开始、结束、停留时长及来源（原文明示、用户设置、建议），保留预约与锁定约束。

首版检查三类问题：地点不明确或错城错类；明示时间与停留／交通冲突；路线不可用或单段交通过长。前站结束时间加交通时间才能与下一站开始比较；没有结束但开始和停留明确时计算结束。信息不足或证据冲突保留待确认。

时间冲突可预览顺延未固定的后续安排。涉及预约、锁定或信息不足时提供手动入口，不擅自改变约束。支持时间、停留、移动、删除、真实地点更换。预览不修改原行程；采纳用一个事务创建版本；旧预览在行程改变后必须拒绝。撤销通过新版本恢复上次修改前内容。

编辑后旧地图标为需要更新，不自动调用路线服务。只有用户点击“更新路线”才为当前行程计算；迟到任务仍属于旧版本。步行和公交均由现有后端提供，差值不超过 10 分钟时优先步行。更新后重新检查相关问题，缺少路线依据不能显示已解决。

## 数据、技术和服务边界

只运行一套 Next.js / React 前端和 FastAPI / Pydantic 后端，采用模块化单体，扩展 `/api/v3/trip-understandings`。PostgreSQL 为所有权、不可变版本、事务、幂等和任务的事实源；Redis 保存缓存、限流及可重建状态。复用已有 worker，不新增运行时多 Agent 或无实际需要的基础设施。

匿名 FULL 创建采用 HttpOnly cookie 和已有所有权能力，每会话每天最多 3 次、同时最多 1 个进行中任务，来源地址另有限流，保留 24 小时。登录保存只领取当前行程及修改，不影响同会话其他草稿；登录保留默认 30 天并在页面说明。用户可随时删除。命令、采纳和撤销有幂等控制，不透明 ETag 防止并发覆盖。

优先复用现有会话、版本和 JSON 存储；必要迁移追加，不重建数据库或删除历史。日志不含秘密、完整原文和未脱敏响应。用户记忆显式开启、结构化、可查看修改删除；原始攻略不默认进入长期记忆、训练或评测。

Qwen 用于真实结构化理解，高德用于地点及路线；沿用已授权配置。不能虚构费用、房态、交通或已验证状态。记录实际失败原因、延迟、token 和估算费用，区分固定回放、真实服务和真人证据。

## 后续能力

核心闭环交付后再做自然语言修改、有来源 RAG 和有限顺路优化。自然语言经 LangGraph 编排理解、允许工具、预览、确认、执行与复检，模型不能直接改库。RAG 先完成来源、更新时间、引用和更新，再比较检索方案。顺路优化只改同日未固定活动，保护预约与锁定，收益基于真实路线数据。

新增外部支出、公开部署和招募试用者另行确认，不影响本地开发与验收。
