# ADR-003：代理校准先于最终真人验收

- 状态：Accepted
- 日期：2026-08-20
- 关联基线：[双入口可验证行程产品与架构重构最终方案](../BreezeTravel_双入口可验证行程产品与架构重构最终方案_2026-08-20.md)

## 决策

将原 M1 的开发阻断改为 `M1-dev`：使用固定版本的 GPT-5.6-sol 独立子 Agent 生成三城模拟行程、受控变异、边界样本和盲评结果，完成开发代理校准后允许推进 P5～P8。

每个代理产物必须带 `synthetic_proxy`、模型标识、prompt/input/output hash 和生成时间；模拟组织者、模拟评审和系统被测路径相互隔离。代理评测通过仅证明离线开发质量，不证明真人可用性、市场价值、真人采纳或公网质量。

原 M1 真人门禁保留为 P8 的最终发布前验收：30 份真实行程、15～20 名真实组织者、真实 consent、真人 finding 和真人 Repair 行为仍由真人产生，不能由 Agent/Judge 代填。

## 后果

- P5～P8 可以在代理门禁通过后继续开发；
- 所有界面、报告、证据包和发布材料必须并列显示 `synthetic_proxy` 与 `human_validated`；
- 未完成真人验收时，产品只能表述为“本地代理验收 candidate”，不能表述为真人验证、生产可用或商业验证；
- 公网部署保持最后一步，并必须同时通过真实验收与公网 E2E。
