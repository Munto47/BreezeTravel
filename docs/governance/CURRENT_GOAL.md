## Outcome

在 P1/P2 已验证的文本主链和可靠 Run 上，闭合截图 OCR 隐私生命周期、四种交通 Evidence、天气与风险来源的受控/snapshot/live Provider 分层证据。

```text
截图/文本 → OCR/Parser → TripBrief 确认 → Provider Adapters
→ EvidenceSnapshot/Receipt → Audit/Advice → Repair → 完整 postcheck
```

## Scope

- PNG/JPEG/WebP 截图输入、OCR 版本/文本框/置信度和终态清理回执；
- 驾车、步行、公交、骑行统一 Provider adapter 与字段级失败语义；
- 天气预报与实时天气预警进入 EvidenceSnapshot，确定性事实与建议性判断分离；非天气风险发现 Provider 在完成数据留存准入前不得进入持久化主链；
- 受控 fixture、固定 snapshot 与 live Provider receipt 分层记录，不互相替代；
- 继续固定北京、上海、杭州、单城市、2～5 人、2～5 天。
- 复用 migration `022`～`024` 与现有公共 HTTP API/schema，不新增 migration 或公共字段；
- live Provider 最小矩阵固定为三城各四种路线、一次天气预报和一次实时天气预警查询，最多 18 次调用；只使用既有高德/和风凭据与免费额度，增量付费预算为 0。

## Non-goals

- 不扩城、不跨城，不新增产品运行时 Agent、消息队列、Kubernetes、GraphRAG 或模型微调；允许开发子代理在固定范围内生成并复核 synthetic/dev/regression 数据；
- 不启动 Builder、Planner、RAG、LoRA、Yjs 或 OR-Tools admission；
- 不修改 frozen blind/oracle，不把 fixture/snapshot 晋级为 live/public/user evidence；
- 不公网部署、不真人招募、不合并 `main`。

## Authority and invariants

- 权威顺序继续遵循仓库 `AGENTS.md`、产品章程、Trip Check Spec/API、Program、Roadmap、Release Gates 与已接受 ADR；
- PostgreSQL 保持 revision、Evidence、receipt、Run 和 lineage 权威；
- 原始截图不得进入数据库、日志或 Git，终态后删除，只保留 hash、OCR 结构和处理回执；
- `UNKNOWN/UNAVAILABLE` 不得转为 PASS，Provider 局部失败必须保留成功事实；
- 新增/付费 Provider、新账号或绑卡、扩大外部数据范围、公共合同、未预批准 migration、生产依赖和证据晋级必须在激活前取得现场批准；既有高德/和风凭据下固定 18 次、零增量费用的开发矩阵可自动执行。

- `P3_SYNTHETIC_OCR_PHASE_GATE`：允许冻结的 `synthetic_stress` OCR 数据集作为 P3 开发阶段退出证据；固定 12 例、三城各 4 例，关键字段 F1 ≥95%，低置信关键字段确认召回率 100%，原图泄漏命中 0；
- `G1_REAL_OCR_CANDIDATE_GATE`：真实来源 OCR 数据仍是 P6 候选版 G1 的必要条件；synthetic 通过后仍保持 `NOT_RUN`，不得写成 `real_ocr_dataset`、真人或发布证据；
- G2：真实 PostgreSQL 的事务、重启回读、清理 receipt 和字段级部分失败语义；
- G3：冻结 snapshot 的离线重放 hash 一致率 100%，重放网络调用为 0；
- G4：只有实际 live 请求/响应 receipt 才可通过；缺少凭据、额度或会产生增量付费时保持 `NOT_RUN`。G4 是 P6 候选证据债，不阻塞 P3 阶段退出；
