# 行程查重建实施计划

唯一产品定义见 [PROJECT_CHARTER](../product/PROJECT_CHARTER.md)，进展见 [CURRENT_GOAL](CURRENT_GOAL.md)。本计划替代旧 G01–G07 日常交付顺序，旧结果原样保留。

## 阶段与可见结果

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| 0 方向切换 | 两仓指导、状态、机器合同与 CI 同步，原状态保护 | 两仓只有同一生效方向；旧候选流程不再限制新功能；立即转入产品实现 |
| 1 可运行新主线 | 精简默认启动、匿名真实输入、持久化、卡片与故障降级 | 统一命令启动真实文字处理，刷新可恢复，固定示例独立 |
| 2 完整体验版 | 新界面、真实地点候选、地图、时间检查、预览采纳、保存撤销 | 用户可独立完成真实行程修改；通过下述完整体验验收 |
| 3 质量与速度 | 代表性样本、遗漏与归属修复、建议质量、并行缓存 | 同一批任务上的质量、延迟与费用对照 |
| 4 AI 能力增强 | 自然语言编辑、带来源 RAG、有限同日优化 | 保持预览确认与事实边界的便利操作 |
| 5 真实使用迭代 | 使用说明、演示、受控试用和反馈 | 基于真实任务改进；招募、公开部署另行确认 |

每个阶段保持完整流程可运行。接口先对齐，前后端可并行但按端到端切片串行集成。不以增加治理或统一历史失败为工作目标。

## 两仓收敛

BreezeTravel 保留 v3 API、账号、数据库、版本、步行／公交、后台任务、隐私和删除。旧房间入口、冻结模块默认启动、原页面壳与重复样式退出新运行主线。

TripCheck 仅迁移经过验证的地图交互、地点联动、局部算法和回归用例；不合并整套后端，不搬入复杂语义后处理，不要求先修完供体历史实验。每项能力接入后单独验证。

## v3 接口实施合同

在 `/api/v3/trip-understandings` 扩展，不建立第二套 API：

- FULL 创建允许匿名；保留独立 DEMO 回放入口和标识。
- 领取当前资源及所有修改，保留同会话其他草稿的能力。
- 地点候选查询绑定资源、活动、版本与时效；选择提交服务端可回读候选凭据，不接受客户端已验证坐标。
- 卡片与命令增加结构化开始、结束、停留及来源，保留锁定／预约；命令增加撤销。
- 地图增加独立地点、活动关联、路线端点关联；不能依赖名称连接。
- 预览／采纳返回结构化前后差异、影响范围与待复检项，按不透明版本条件原子应用。
- JSON 数据优先复用，必要数据库变更追加式迁移；客户端类型与接口同步。

## 完整体验版验收

12 条自动化主流程：北京、上海、杭州各覆盖正常输入、地点歧义、时间冲突、修改与恢复。每城另用至少一份非固定示例运行真实模型和地图闭环。两者分别报告。

必须验证：

1. 保留显式日期、主要地点和顺序；取消和备选不自动成为执行路线；未整理内容诚实显示。
2. “10 点开始游览两小时、交通 20 分钟、11 点到下一站”检出冲突；信息不足不算可行。
3. 待确认地点通过真实候选选择可解决；错城、错类、句子和 URL 不可假装匹配。
4. 单地点、缺少时间、地图局部失败时仍可操作；有对应重试，不阻塞已有内容。
5. 预览不改变原文档；采纳、撤销、刷新恢复一致；预约锁定不被自动移动。
6. 连续提交、网络中断、旧预览和迟到任务不会重复修改或覆盖当前结果。
7. 匿名隔离、登录领取、同会话多草稿、过期清理与删除正确。
8. 编辑不自动调用路线，手动更新完成后基于当前证据复检。
9. 1440px、1280px、390px、360px 均可完成核心任务，无横向溢出及多层嵌套滚动。

以上通过即交付完整体验版，不等待后续自然语言、RAG、统计评测或旧候选流程。机器合同 PASS 仅代表文档一致性，不能替代以上验证。

## 质量与速度

首版记录完整结果、失败、延迟与费用。随后建立 60 条代表性样本：40 开发、20 保留，按来源及表达模板分开；测试样本用于调试后转入开发集。比较规则基线、结构化模型、地点与事实约束完整方案。

报告完整率、地点错误率及自动处理覆盖、有效建议比例、人工修改量、P50/P95 延迟、单次完成费用。固定回放、真实服务、真人体验分别披露。优化指标不提前阻挡完整产品交付。

与新行为冲突的旧测试按新合同修改并记录原因，保留安全验证和原历史失败。单个问题两轮不同修复无改善则缩小复现、调整方法，允许明确的局部待确认，不能静默遗漏或假成功。

## 运行与恢复

本地默认只含 Web、API、必要 worker、PostgreSQL、Redis。真实环境使用已有授权 Provider；演示环境固定回放单独入口。统一启动、停止、故障重启和数据恢复说明在阶段 1 交付；不输出密钥、不覆盖现有环境、不删除旧数据库。

创建、修改、采纳、撤销使用幂等；不透明 ETag 防并发覆盖。匿名 24 小时、3 次／日、1 进行中；登录默认 30 天。新增费用、公开部署、招募另行确认。
